# Status：开发状态的编写与维护

本文说明开发状态文档（Status）的用途、应包含的内容，以及更新和收尾方式。需要了解项目当前在做什么、实际做到哪里、后续准备做什么时，可通过这份文档进入开发工作。

## Status 是什么

Status 是项目开发状态的统一入口，记录当前工作、进展与验收、待决策与阻塞，以及后续安排。

Plan 安排如何完成一项工作，Status 记录项目实际状态和后续安排。Status 可以概述目标并链接设计与计划，但不重新定义产品范围、功能契约或实施任务。

## 文件与职责范围

默认保存在 `docs/STATUS.md`。项目进入持续开发后，维护一份开发状态文档，统一记录当前进展和后续安排。

文档应标注最后更新日期。日期变化应对应实际内容变化，不应只刷新日期而不更新状态。

## Status 应写什么

| 内容 | 应回答的问题 | 填写边界 |
| --- | --- | --- |
| 当前工作 | 当前在做什么，处于什么状态？ | 概述目标和状态，链接对应 Spec、Plan，不复制完整设计。 |
| 进展与验收 | 已完成什么，实际验证了什么？ | 记录结果、验证范围和尚未验证的内容，按需引用提交或验证记录。 |
| 待决策与阻塞 | 哪些问题需要决定，哪些条件阻止继续推进？ | 区分待决策、实际阻塞和普通待办；没有时写“无”。 |
| 后续安排 | 接下来做什么，优先顺序是什么？ | 说明下一项工作、启动条件和暂未安排的方向，不展开实施任务。 |

推荐结构如下：

```markdown
# 开发状态

最后更新：<YYYY-MM-DD>

## 当前工作

## 进展与验收

## 待决策与阻塞

## 后续安排
```

已确认的要求、观察到的事实和待评估的建议应明确区分。列入后续安排不代表具体方案已经确认，也不代表相关实现已经存在缺陷。

### 参考示例：个人笔记产品

以下进展、验证结果和后续安排均为示例，不表示实际项目已经完成或承诺这些工作。

```markdown
# 开发状态

最后更新：2026-10-05

## 当前工作

当前交付公开分享笔记功能，包括创建链接、只读访问和撤销。
功能实现完成，自动化验证通过，浏览器完整流程验收待执行。

关联资料：

- specs/note-sharing.md：功能行为与验收标准。
- plans/note-sharing.md：实施任务与验证安排。

## 进展与验收

- 分享链接创建、公开读取和撤销已实现，界面已接通。
- 自动化测试覆盖创建、撤销、已撤销链接访问和无权访问。
- 受影响代码的类型检查通过。
- 两个浏览器会话之间的分享流程尚未验证，不能宣称全部验收完成。

## 待决策与阻塞

无。浏览器验收是待执行工作，当前没有阻止其执行的条件。

## 后续安排

1. 按分享 Plan 完成双会话验收，记录实际结果。
2. 分享验收结束后，评估断网、保存失败和重启后的恢复行为。

恢复评估尚未开始，不预设已经存在数据丢失，也不提前决定恢复机制。
单篇笔记摘要是保留的产品方向，实施顺序尚未安排。
```

## Status 不应写什么

- 不复制 Spec 的完整行为规则或 Plan 的任务清单。
- 不把尚未调查的疑点写成确定缺陷。
- 不把计划、建议和已观察到的事实混写成完成结果。
- 不以提交、启动成功或单项检查通过代替功能验收。
- 不将未确认的日期写成排期承诺。
- 不持续堆积旧阶段的全部执行过程。

## 与其他文档的分工

| 文档 | 与 Status 的关系 |
| --- | --- |
| PRD | 定义产品目标和范围；Status 记录开发进展及工作优先顺序。 |
| Architecture | 定义系统结构和约束；Status 记录架构调整的实际推进情况。 |
| Spec | 规定功能行为和验收标准；Status 记录实际验证范围和结果。 |
| Decision | 保存重要选择的理由；Status 引用影响当前工作的决策。 |
| Plan | 安排任务和验证；Status 概述结果、阻塞及后续安排。 |

Plan 可记录任务勾选状态，Status 不复制逐项清单。PRD 的当前能力只概述已具备的产品能力，不替代开发进展和验收记录。

## 如何使用 Status

接手工作时，读取当前状态、验收边界和阻塞，再通过文档链接进入设计与计划。状态记录不代替对代码和实际行为的必要核实。

如果自动化验证通过，但真实使用尚未验收，应保留这一边界，不将其概括为全部完成。准备启动后续工作时，应确认需求和范围；列入安排不表示已经具备实施条件。

## 何时维护 Status

| 变化 | 状态文档的维护方式 |
| --- | --- |
| 开始当前工作 | 更新目标、状态和资料入口。 |
| 完成工作项或获得验证结果 | 更新结果与验收情况，不复制完整执行日志。 |
| 出现或解除阻塞 | 更新阻塞说明和受影响的安排。 |
| 优先顺序、目标或依赖变化 | 更新后续安排，简述变化原因。 |
| 当前工作结束或切换 | 保留结果、验收边界及未完成事项，更新当前工作。 |

需要追溯的旧阶段状态可存入 `docs/archive/`。当前文档保留继续开发所需的信息；仍有效的未完成事项应保留或链接接续计划，不随历史记录归档而遗失。
